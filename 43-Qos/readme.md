# QoS Configuration Lab – DSCP Marking and Priority Queuing

## 📌 Lab Overview

This lab demonstrates basic **Quality of Service (QoS)** configuration on a Cisco router using:

* DSCP marking
* Class maps
* Policy maps
* Priority queuing
* Bandwidth allocation
* Packet verification using Simulation Mode in Cisco Packet Tracer

> **Note:** QoS configuration is not part of the CCNA exam objectives, but this lab provides practical experience with basic QoS concepts.

---

## 🖥️ Topology

```text
PC1                    R1                  R2                 Server
 |                     |                   |                    |
 |                     |                   |                    |
SW1 ---- G0/0/1 ---- G0/0/0             G0/0/0 ---- G0/0/1 ---- SW2
                       |                   |
                 172.16.0.1/30       172.16.0.2/30
```

## 🎯 Objectives

Configure QoS on **R1** and apply the QoS policy **outbound on interface G0/0/0**.

The required QoS configuration is:

1. Mark **HTTPS traffic** as **AF31**

   * Provide a minimum of **10% bandwidth** using a priority queue.

2. Mark **HTTP traffic** as **AF32**

   * Provide a minimum of **10% bandwidth**.

3. Mark **ICMP traffic** as **CS2**

   * Provide a minimum of **5% bandwidth**.

4. Use **Simulation Mode** to verify the DSCP markings of packets generated by PC1.

# 🔧 Step 3 – Create Class Maps

Class maps identify the traffic that will receive different QoS treatment.

## HTTPS Traffic

HTTPS uses TCP port **443**.

```cisco
class-map match-any HTTPS-TRAFFIC
 match protocol https
```

## HTTP Traffic

HTTP uses TCP port **80**.

```cisco
class-map match-any HTTP-TRAFFIC
 match protocol http
```

## ICMP Traffic

```cisco
class-map match-any ICMP-TRAFFIC
 match protocol icmp
```

---

# 🔧 Step 4 – Create the QoS Policy

Create a policy map:

```cisco
policy-map QOS-POLICY
```

### HTTPS – AF31

AF31 corresponds to DSCP value **26**.

```cisco
 class HTTPS-TRAFFIC
  set dscp af31
  priority percent 10
```

The `priority` command places HTTPS traffic into a low-latency priority queue and guarantees the configured percentage of bandwidth.

---

### HTTP – AF32

AF32 corresponds to DSCP value **28**.

```cisco
 class HTTP-TRAFFIC
  set dscp af32
  bandwidth percent 10
```

---

### ICMP – CS2

CS2 corresponds to DSCP value **16**.

```cisco
 class ICMP-TRAFFIC
  set dscp cs2
  bandwidth percent 5
```

Complete policy:

```cisco
policy-map QOS-POLICY
 class HTTPS-TRAFFIC
  set dscp af31
  priority percent 10

 class HTTP-TRAFFIC
  set dscp af32
  bandwidth percent 10

 class ICMP-TRAFFIC
  set dscp cs2
  bandwidth percent 5
```

---

# 🔧 Step 5 – Apply QoS Policy

The QoS policy must be applied **outbound on R1's G0/0/0 interface**.

```cisco
interface gigabitEthernet 0/0/0
 service-policy output QOS-POLICY
 exit
```

Save the configuration:

```cisco
end
write memory
```

or:

```cisco
copy running-config startup-config
```

# 🔍 Step 6 – Verify the QoS Configuration

Check the policy map:

```cisco
show policy-map
```

Check the interface configuration:

```cisco
show running-config interface gigabitEthernet 0/0/0
```

Check policy-map statistics:

```cisco

```

The last command is particularly useful because it displays:

* Packets matched by each class
* Bytes matched
* Queue statistics
* Bandwidth allocation
* Priority queue information
* DSCP marking activity

# 🧠 Important QoS Concepts

### DSCP

**Differentiated Services Code Point (DSCP)** is a field in the IP header used to classify and prioritize packets.

Common markings used in this lab:

```text
AF31 = DSCP 26
AF32 = DSCP 28
CS2  = DSCP 16
```

### Priority Queue

The command:

```cisco
priority percent 10
```

places the traffic into a priority queue and allocates up to the configured percentage of interface bandwidth to that class.

### Bandwidth Queue

The command:

```cisco
bandwidth percent 10
```

provides the class with a minimum bandwidth allocation during congestion.
